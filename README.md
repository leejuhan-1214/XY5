# XY5 — 실제 지도 기반 도시 열환경 탐색

XY5는 실제 지도 위에 위성 지표면 온도와 높이가 등록된 건물을 함께 표시해 도시 열환경을 살펴보는 웹 앱이다. [배포된 사이트](https://leejuhan-1214.github.io/XY5/)는 별도 서버 없이 GitHub Pages에서 실행된다. 이 문서는 다음 개발자나 Claude가 **현재 해결하려는 문제, 데이터의 의미, 구현 범위와 한계, 수정 지점**을 혼동하지 않도록 작성했다.

## 지금 해결하려는 문제

이 프로젝트의 출발점은 다음 세 가지 연구 질문이다.

1. 도시의 공간 구조와 지표 특성에 따라 열이 어디에 축적되고, 어떻게 확산·이동하는가?
2. 도시 열환경을 모델링했을 때 고온 지역의 분포와 열 이동 양상이 실제 자료와 어느 정도 일치하는가?
3. 제한된 범위에서 열섬 저감 요소의 위치와 배치를 어떻게 조정해야 효과적인가?

현재 사이트는 **첫 단계인 실제 관측 자료의 공간적 탐색**을 구현했다. 사용자가 지도를 이동하면 현재 화면을 대상으로 Landsat 지표면 온도를 요청하고, 실제 OSM 높이 태그가 있는 건물을 3D로 표시한다. 지점 클릭으로 해당 위성 픽셀의 온도와 촬영일을 확인할 수 있다. 같은 지도에서 지면·지붕 재료를 바꾸는 시나리오도 비교할 수 있다.

다만 위 세 질문에 대한 과학적 답을 완성한 상태는 아니다. 현재 화면의 색은 관측 위성 영상이며, 시간에 따른 열의 이동을 계산한 결과가 아니다. 재료 변경 결과는 가정한 태양 복사·증발 조건에서 **단위면적당 에너지 입력 차이(W/m²)**를 계산한 예시이지, 실제 온도 저감량이나 미래 온도 예측이 아니다. 현장 관측과 모델을 정량 비교하는 검증이나 최적 배치 계산도 아직 없다. 화면과 문서에서 이 구분을 유지해야 한다.

### 연구 질문별 현황과 다음 과제

| 연구 질문 | 현재 가능한 일 | 아직 해결되지 않은 부분 |
| --- | --- | --- |
| 열 축적·확산·이동 | 화면 내 실제 지표면 온도 분포와 높이 등록 건물의 위치를 함께 관찰 | 풍향·풍속, 일사·그늘, 지형, 재료·토양수분, 시간 변화 등을 포함한 열수지/이류·확산 모델이 없다. 지도 애니메이션을 열 이동의 증거로 해석하면 안 된다. |
| 모델과 실제 자료의 일치 | 관측 Landsat 픽셀 온도, 촬영일, 유효 픽셀 통계를 표시 | 현재 독립적인 예측 온도장이 없어 관측과 예측의 MAE/RMSE, 공간 패턴 일치도, 시기별 검증을 계산할 수 없다. 동일 시각·위치의 기상/현장 측정값과 비교해야 한다. |
| 저감 요소의 최적 배치 | 선택한 한 지면 또는 지붕에 재료를 바꾼 경우의 단순 에너지 입력 차이를 표시 | 복수 위치·면적의 배치, 예산·면적 제약, 주변으로 퍼지는 효과, 실제 온도 변화, 최적화 목적함수가 구현되지 않았다. 원의 반경은 현재 시각화 범위이며 산식의 W/m² 결과는 바뀌지 않는다. |

**우선순위가 높은 실제 문제**는 관측 시점이 장소마다 다를 수 있다는 점, 결측/구름 때문에 화면 전체에 값이 없을 수 있다는 점, OSM 높이 태그가 없는 건물은 3D로 나타나지 않는다는 점, 재료의 실제 현장 상태를 알 수 없다는 점이다. 위성 지표면 온도와 사람이 체감하는 높이의 기온도 서로 다른 변수다. 연구용 결과를 주장하려면 이 문제를 먼저 다루고 출처·불확실성을 함께 보여줘야 한다.

## 사용자 요구사항과 현재 동작

- 모식도가 아닌 실제 지도를 바탕으로 하고, 특정 사각형 지역에 고정하지 않는다. 이동·확대·축소한 **현재 화면**의 관측 범위를 다시 요청한다.
- 지도에 등록된 높이가 있는 건물만 모든 지원 지역에서 3D로 나타낸다. 높이를 층수로 추정하거나 임의 높이를 채우지 않는다.
- 밝은 지도와 간결한 UI를 사용하며 일반 화면에서 페이지 스크롤 없이 주요 제어를 볼 수 있도록 한다. 전체 화면 버튼도 있다.
- 분석 기준일의 기본값은 사용자의 현재 날짜다. 이는 **자료 검색 기준일**이며 측정일과 같다는 뜻이 아니다. 각 픽셀에 실제로 사용한 위성 촬영일을 별도로 표시한다.
- 관측 패널을 접어도 지도 클릭 온도를 볼 수 있도록 간단한 온도 카드가 남는다.
- 지면·지붕 재료 비교는 이전 별도 사이트로 이동하지 않고 현재 지도에서 실행한다.

| 화면 요소 | 출처와 의미 | 주의점 |

지도에서 관측 온도와 재료 계산 결과를 같은 색 또는 같은 단위처럼 취급하지 말 것. 특히 재료 변경으로 `-360 W/m²`가 나왔다고 `-360°C`나 일정한 `°C` 저감으로 바꾸면 안 된다. 지붕 아래 실내 온도, 보행자 기온, 체감 온도도 이 앱에서 측정하지 않는다.

## 빠른 실행과 배포

정적 HTML/CSS/JavaScript ES 모듈 프로젝트다. Node.js 18 이상을 권장하며 GitHub Actions에서는 Node.js 22를 쓴다. 테스트에 npm 패키지 설치가 필요하지 않다.

```bash
python -m http.server 8000
# 브라우저에서 http://localhost:8000/
```

`npm start`도 가능하지만 내부적으로 `npx serve .`를 실행하므로 로컬 환경에 따라 serve 설치/다운로드가 필요할 수 있다. `file://`로 직접 열면 ES 모듈이나 외부 요청이 동작하지 않을 수 있다. 지도·위성·건물 데이터는 실행 중 외부 서비스에 요청하므로 네트워크가 필요하다.

```bash
npm test
```

`.github/workflows/pages.yml`은 `main`에 푸시하거나 수동 실행하면 테스트 후 GitHub Pages에 정적 파일을 배포한다. 배포 주소는 위의 Pages URL이다. 작업 전 `git status`와 배포 브랜치를 확인하고, 변경 후 테스트·브라우저 검증·Pages 실행 결과를 확인할 것.

## 현재 지도와 관측 파이프라인

`src/observed-app.js`는 OpenFreeMap `https://tiles.openfreemap.org/styles/bright`를 사용한다. 초기 중심은 경도 126.7065, 위도 37.4479, 줌 15.35, 피치 55°, 방위 -24°이며 URL 해시로 카메라 상태가 저장된다. 사용자가 움직인 현재 화면을 기준으로 분석하며 줌 8 미만에서는 관측 요청을 하지 않는다. 이동이 끝난 뒤 약 450ms를 기다렸다 요청하고, 새 요청이 생기면 이전 요청을 `AbortController`와 요청 번호로 무효화한다. 최근 화면 결과는 제한된 개수로 캐시한다.

`src/viewport-data.js`의 `frameFor`는 화면 경계를 Web Mercator(EPSG:3857)로 바꿔 가로·세로 32~256픽셀 요청 격자를 만든다. Microsoft Planetary Computer STAC에서 `landsat-c2-l2`를 분석 기준일 전후 32일 범위로 찾고, 장면 구름 비율 80% 미만, 최대 100개를 받은 후 Landsat 8/9 `L2SP`와 열 밴드·`QA_PIXEL`이 있는 장면을 고른다. 기준일과의 거리 및 구름 비율로 순위를 정해 최대 4개 장면을 사용한다. 이는 가능한 장면을 찾는 정책이지 당일 관측을 보장하는 정책이 아니다.

자료 응답은 열 밴드, 품질 비트, 유효 마스크로 구성된 uint16 NPY다. 유효 조건은 마스크 `> 0`, 열 DN `>= 293`, `(QA_PIXEL & 63) === 0`이다. 유효 DN을 다음 식으로 바꾼다.

```text
LST(°C) = DN × 0.00341802 + 149 − 273.15
```

결측 픽셀은 `null`로 남긴다. 여러 장면은 앞 장면의 유효 픽셀을 보존하고 뒤 장면으로 결측만 채운다. 각 픽셀의 실제 장면 촬영일을 추적한다. 래스터를 캔버스로 그려 지도 위에 약 0.58의 투명도로 올리고, 고정 온도 색 기준(24·30·36·42·50°C)을 사용한다. 통계는 화면의 유효 투영 픽셀에 대한 값이지 도시 전체의 대표 온도가 아니다. 검색 결과의 전체 페이지를 순회하는 구조는 현재 없으므로, 특정 날짜의 모든 장면을 포괄한다고 가정하지 말 것.

## 건물 3D와 클릭 동작

배경 지도 건물 레이어 대신 Overpass에서 실제 `building`/`building:part` 형상과 `height` 태그를 조회한다. `height`는 미터 또는 피트로 명시된 값만 변환한다. `building:levels`에서 층고를 임의 추정하지 않는다. 닫힌 다각형과 멀티폴리곤의 내부 빈 공간도 처리한다. 3D 요청은 줌 13 이상, 조회 영역 160 km² 이하에서만 수행한다. 요청 간격을 두고 제한적으로 캐시하며 예비 Overpass 서버가 있다. 서버가 느리거나 오류를 내면 건물이 일시적으로 나타나지 않을 수 있다. 높이 태그가 없는 건물은 3D로 보이지 않는 것이 현재 정책이다.

지도 소스·레이어 이름은 `recorded-buildings`, `building-footprints`, `recorded-heights`다. 건물 클릭은 건물 형상을 찾는 데 쓰이지만 표시하는 온도는 **건물 자체를 측정한 온도**가 아니라 그 위치에 대응되는 Landsat 지표면 픽셀 값이다. 관측 패널이 닫힌 경우에도 이 값을 간단한 카드에서 확인할 수 있어야 한다.

## 재료 변경 모드의 정확한 의미

현재 지도에서 재료 모드를 켜면 하나의 지면 지점이나 높이 등록 건물 지붕을 선택한다. 지면은 반경 10~100m의 원형 영역으로 표시하고, 지붕은 OSM 건물 형상 위의 얇은 층으로 표시한다. 기본 비교는 지면의 아스팔트→차열 포장, 지붕의 어두운 지붕→밝은 페인트다. 실제 기존 재료를 판독한 것이 아니므로 UI에도 **가정한 기존 재료**라고 표기한다.

계산은 `src/material-scenario.js`의 단순 예시 모델이다. 기본 가정 일사량 `I = 800 W/m²`, 수분 계수 `m = 0.4`에서 재료별 반사율 `α`와 증발 항을 이용한다.

```text
energy(material) = (1 − α) × I − evaporation × m
difference = energy(proposed) − energy(baseline)   [W/m²]
```

예를 들어 반사율 0.05인 아스팔트를 0.50인 차열 포장으로 바꾸고 다른 항이 같다면 760→400 W/m², 차이 -360 W/m²다. 이는 매우 단순화된 표면 에너지 입력 비교다. 방사·대류·전도·열용량·바람·그늘·주변 온도 피드백을 풀지 않고 `°C`를 출력하지 않는다. 재료표에 다른 성질이 있더라도 이 산식에서 사용하지 않는 속성은 온도 효과를 입증하지 않는다. 원의 반경은 선택 영역의 시각화이며 단위면적당 W/m² 산식은 변하지 않는다. 재료별 지도 색도 계산된 온도 색이 아니다.

## Claude 또는 다음 개발자의 수정 체크리스트

1. **먼저 변수의 의미를 정한다.** 위성 LST, 기온, 모델 예측, 시나리오 W/m²를 서로 다른 상태·단위·범례로 유지한다. 연구 질문 2·3을 구현할 때 예측값·실측값·오차·불확실성을 분리한다.
2. **데이터 시점과 품질을 보존한다.** 기준일과 실제 촬영일을 함께 표기하고, 구름/결측을 임의 색이나 주변값으로 채우지 않는다. 혼합 장면이면 픽셀별 출처를 고려한다.
3. **현재 화면 기반 동작을 지킨다.** 카메라 이동 시 이전 요청 취소, 새 범위 요청, 화면 크기 변경/전체 화면 후 `map.resize()`와 오버레이 위치를 확인한다. 고정된 한 지역 자료로 되돌리지 않는다.
4. **건물 높이를 만들지 않는다.** 사용자 선택은 높이 태그가 있는 건물만 3D 표시하는 것이다. OSM에 없는 높이를 층수나 랜덤 값으로 채우려면 요구사항 변경과 명확한 표시가 먼저 필요하다.
5. **UI 상태를 함께 검사한다.** `index.html`의 요소 ID와 `src/observed-app.js` 조회 코드, 패널 접힘 상태 및 `materials-mode` 클래스, 모바일·낮은 화면 CSS를 같이 확인한다. 지점 클릭 온도는 접힌 상태에서도 보이게 한다.
6. **새 모델을 만들면 검증한다.** 동일 시공간의 독립 관측 자료를 확보하고 학습·검증 시점을 분리해 MAE/RMSE와 고온 지역의 위치 일치도를 보고한다. 열 이동을 주장하려면 바람·일사·경계조건 및 시간 단계가 있는 모델과 검증이 필요하다. 최적 배치는 복수 개입, 면적/비용 제약, 목적함수와 공간적 영향 범위를 명시해야 한다.
7. **변경 후 확인한다.** `npm test`, 브라우저에서 지도 이동·확대·축소·건물 클릭·패널 접기·재료 변경·전체 화면·모바일 높이를 시험한다. 외부 API의 429/504 또는 무자료 상태에서도 화면이 오해를 유발하지 않는지 확인한다.
