# XY5 — 구월동 도시 열환경 연구

XY5는 **관측 자료 → 고온 군집 → 시간별 모델 → 저감 자원 배치 → 관측과의 오차 비교**를 연결하는 정적 웹 앱이다. Landsat 지표면온도(LST), 실제 Sentinel-2 지수, 공식 세분류 토지피복 자료를 확인하고, 가정 기반 모델의 결과와 한계를 함께 살펴본다.

- [자유 이동 관측 지도](https://leejuhan-1214.github.io/XY5/) — 현재 화면의 위성 장면, 상대적 고온 영역, A/B 위치 비교, 높이 등록 건물, 한 지점 재료 실험.
- [구월동 연구실](https://leejuhan-1214.github.io/XY5/research.html) — 같은 경계·격자에서 7개 연구 질문, 고온 군집, Model 1·2·3, 배치 탐색과 보정 없는 관측 비교.
- [재현·방법 문서](https://leejuhan-1214.github.io/XY5/methodology.html).

**구현된 계산 기능과 과학적으로 검증된 결론은 다르다.** 현재 모델은 검증된 도시 온도 예측기가 아니다. 사이트에서 오차와 가정을 확인할 수 있지만, 현장 측정·다양한 시기·독립 공간 검증을 완료했다는 의미는 아니다.

## 연구 목적과 용어

출발점은 도시의 공간 구조와 지표 특성이 열의 분포에 어떤 관계를 보이는지, 그 분포를 모델이 어느 정도 재현하는지, 같은 저감 자원을 어디에 놓으면 모델상 효과가 달라지는지 탐구하는 것이다.

이 연구에서 다루는 중심 변수는 **지역의 지표면온도와 도시 열환경**이다. 넓은 대기권 고기압 정체를 뜻하는 기상학적 ‘열돔’의 발생·지속을 이 사이트로 판정하지 않는다. 그러한 주장을 하려면 기압·대기 순환·평년 대비 기온 등 별도 자료가 필요하다. 도시 내부 상대적 고온 영역만으로 도시와 비도시의 기온 차이까지 측정했다고 말하지 않는다.

## 빠른 실행과 확인

Node.js 22 이상과 정적 HTTP 서버를 사용한다. 브라우저 실행에 npm 패키지 설치는 필요하지 않다.

```bash
python -m http.server 8000
# http://localhost:8000/ 및 http://localhost:8000/research.html
```

```bash
npm test
python tests/test_research_data.py
```

Python 데이터 재현·검사는 `numpy`, `Pillow`가 필요하다. `file://`로 직접 열면 ES 모듈·Web Worker·fetch가 동작하지 않을 수 있다. 자유 이동 지도는 외부 지도·위성·건물·기상 서비스 연결이 필요하다. 연구실의 정합 자료는 저장소의 JSON에서 읽고 열모델은 Web Worker에서 실행한다.

검사는 장면 보존·순위·취소·다음 후보 복구, 결측·날짜·좌표 정합, 군집 면적·잡음점·통계, 동일 자원·예산, 난수 재현성, 관측값 누출 방지를 포함한다. 테스트 통과는 소프트웨어 동작 확인이며 모델의 현장 정확도 입증이 아니다. 배포 전 데스크톱·모바일에서 지도 이동, 자료 실패, A/B 비교, 연구실 계산과 내보내기를 확인한다.

`.github/workflows/pages.yml`은 PR에서 테스트하고, `main` 푸시 또는 수동 실행 시 테스트를 통과한 런타임 파일을 GitHub Pages에 배포한다. `_site`에는 연구실과 `data/research-inputs.json`이 포함된다. 개발 스크립트·테스트·중복 사본 `urban-heat-potential-lab/` 등은 배포에서 제외한다. `data/observations.json`·`data/buildings.geojson`은 개발·검사용 원자료이므로 배포되지 않는다.

## 정합된 구월동 연구 자료

`data/research-inputs.json`은 자료 상태·원 URL·SHA-256·촬영 시각·유효 비율·정합 방법을 저장한다. 다음 수치는 현재 포함된 파일 기준이며 재생성하면 바뀔 수 있다.

### 경계와 분석 격자

- 경위도 범위: `[126.6925639, 37.4340681, 126.7218288, 37.4610653]` (서·남·동·북).
- EPSG:4326, 24 × 18 = 432셀, 북쪽부터 행 우선. 셀 간격은 대략 동서 108 m × 남북 167 m다.
- 실제 연구 마스크는 **246셀**이다. `data/research-boundary.geojson`의 OSM 구월동 relation 8857846 안에 중심점이 있는 셀만 포함한다. OSM 경계 버전 5, 원자료 시각 2023-06-25이며 공식 지적 측량 경계는 아니다.
- 마스크 안 전체 셀 면적 합은 약 **4.416 km²**다. 경계 셀을 다각형으로 잘라 계산하지 않으므로 구월동의 공식 면적이 아니다.
- 예전 `data/guwol-boundary.geojson`은 단순 연구 사각형이다. 실제 법정동 다각형으로 사용하지 않는다. 연구실은 `research-inputs.grid.insideBoundary`를 모델에도 동일하게 적용한다.

NDVI는 `(B08 − B04) / (B08 + B04)`, NDBI는 `(B11 − B08) / (B11 + B08)`다. 현재 연구실의 Sentinel-2 값은 실제 Sentinel-2 원자료로 새로 생성한 값이다. 예전 `guwol-data.json`의 Landsat 기반 지수 이름을 바꾼 것이 아니다. Landsat 선택일과 Sentinel-2 촬영일이 다르면 지수와 LST의 동시 관계 계산을 보류한다. 토지피복·OSM의 연도 차이는 별도로 표시한다.

Landsat 온도 변환식은 다음과 같다.

```text
LST(°C) = DN × 0.00341802 + 149 − 273.15
```

**ST_QA 불확실도 밴드는 현재 가져오거나 분석하지 않는다.** QA_PIXEL 구름 제거와 온도 추정 불확실도 분석은 서로 다른 처리다.

## 고온 영역과 DBSCAN

`src/research-analysis.js`는 관측값·모델값을 혼합하지 않고 다음을 계산한다.

- 고온 임계값은 유효 화소의 백분위 또는 명시적인 고정 온도다. 기본 P90 이상이며 동률 때문에 고온 화소가 정확히 10%가 아닐 수 있다.
- 거리 계산은 지역 중심의 방위정거 투영에 의한 실제 미터 좌표를 사용한다. 기본 eps 250 m, minPts 3(자기 자신 포함). 연구실에서 값을 조절할 수 있다.
- 결측·마스크 밖은 군집화에서 제외한다. 잡음점은 별도로 세고 군집별 통계에서 제외한다. 고온 전체 면적에는 고온 잡음점도 들어갈 수 있으므로 군집 면적 합과 항상 같지는 않다.
- 군집별 위치(면적 가중 중심), 셀 수, 셀 면적 합, 평균·최고온도를 제공한다. GeoJSON은 셀 모양과 빈 공간을 보존한다. 면적은 위도에 따른 구면 셀 면적이다.
- 큰 래스터에서 모든 이웃 쌍을 저장하지 않도록 공간 버킷과 핵심점 연결을 사용한다. 군집은 eps·minPts·격자·임계값을 기록해야 재현할 수 있다.

자유 지도는 **현재 화면 안의 단일 촬영 장면**에서만 고온 영역을 계산한다. 유효 표본 30개 이상·화면 자료 범위 30% 이상이라는 표시 기준을 사용한다. 이것은 통계적 신뢰도 보증이 아니다. 화면 이동 시 분석 범위와 P90이 바뀐다. 보라색 윤곽은 P90 이상 전체이며 군집 표는 DBSCAN 결과다.

세 모델의 고온 면적 비교에는 **Model 1의 평가 시각 P90**을 한 번 정하고 그 값을 모든 모델·시간에 고정한다. 각 모델의 상위 10%를 따로 골라 냉각 면적이 감소했다고 주장하지 않는다.

## CA 유사 열모델

`src/research-model.js`는 관측 LST를 읽지 않는 별도의 모델이다. 각 셀의 지표 온도, 기층 온도, 공기층 온도를 두고 연속값을 반복 갱신한다. 격자 간 갱신이라는 의미에서 CA 유사 모델이며, 보존법칙을 완전히 검증한 도시 미기상 CFD 모델은 아니다.

### 실제 계산하는 과정

- 지표: 흡수 일사, 장파 복사, 공기와의 현열 교환, 가정 증발, 기층 전도, 가정 인공열, 이웃 지표와의 측방 전도.
- 기층: 열 저장, 지표와의 교환, 초기 기층 온도로의 약한 완화.
- 공기층: 지표 현열, 상류차분 이류, 수평 확산, 배경 기온으로의 완화. **표면 자체를 바람으로 이동시키지 않는다.**
- 수목 셀의 일사에 간단한 그늘 계수 0.45를 사용한다. 상세 건물 그림자·다중 복사는 계산하지 않는다.

최대 시간 간격은 30초이며 이류·확산·교환을 포함한 안정성 비율이 0.45 이하가 되도록 더 줄인다. 결과에는 최대 비율과 실제 최소 시간 간격을 기록하고 비정상적인 온도·비유한값을 오류로 처리한다. 이것은 수치 발산 방지 검사이며 현장 검증을 대신하지 않는다.

경계조건은 지표·확산 무유속, 공기 유입 배경 기온, 공기 유출 상류차분이다. 공기는 900초 척도로 배경 기온에 완화된다. 모든 시나리오는 00시 기온으로 지표·기층·공기를 동일하게 초기화하므로 전날의 열 저장을 반영하지 않는다.

주요 가정은 공기층 깊이 30 m, 풍속 감소 계수 0.25, 공기 확산계수 5 m²/s 등이다. 계수 전체는 `MODEL_ASSUMPTIONS`와 `src/materials.js`에 있다. 재질 분류와 물성은 현장 조사로 확인한 값이 아니다. 모델은 시간별 공기 현열 수송 벡터도 반환한다. 화면 화살표는 가정한 30 m 공기층의 배경 대비 열 수송량(W/m)을 세 지도에 공통 길이 척도로 그린다. 음의 온도 편차에서는 벡터가 바람과 반대일 수 있다. 바람장은 균일하며 세 모델에 동일하므로 실제 이동경로 차이를 검증한 기능으로 표현하지 않는다.

## Model 1·2·3와 배치 탐색

| 모델 | 정의 | 변경 조건 |
| --- | --- | --- |
| Model 1 | 기존 가정 재료의 기준 도시 | 저감 재료 추가 없음 |
| Model 2 | 정해진 위치의 재료만 변경 | 결정적 순서로 고른 허용 셀에 고정 재료 수량 적용 |
| Model 3 | 같은 자원의 위치를 탐색 | Model 2와 동일한 재료별 수량·허용 표면 종류·상대비용을 유지하며 배치 변경 |

세 모델은 동일한 246셀 마스크, 격자, 2024-08-29 기상, 초기조건, 계산 기간을 사용한다. 24시간을 계산해 시간별 값을 저장한다. UI 기본 평가 시각은 11시, 개입 비율은 10%, 난수 시드는 42다. 연구실 초기 로딩 후 모델과 관측 비교를 자동 계산하며, 평가 시각(1–23시)과 결과를 보는 시각(0–23시)은 별도 조절한다. 결과의 임계값과 최적화 목적은 실행 당시 평가 시각에 고정되며 시간 그래프를 탐색한다고 재최적화되는 것은 아니다.

### 자원과 제약

- 변경 가능 셀은 기준 재질이 검은 지붕·아스팔트·콘크리트인 경계 내부 셀이다. 물·기존 녹지·경계 밖은 제외한다.
- 변경 셀 수는 `floor(허용 셀 수 × 변경 비율 / 100)`이다. UI는 0–30% 범위를 제공한다.
- 지붕 자원은 녹화 지붕·밝은 지붕 재료, 지면 자원은 투수·차열 포장으로 구성한다. Model 2에서 만든 동일 재료 수량을 Model 3에 유지한다. 지붕 자원을 지면에 놓거나 같은 셀에 중복 설치하지 않는다.
- 비용은 셀당 가정 상대단위다. 실제 원화·공사 견적이 아니다. 셀들의 위도별 면적은 미세하게 다르므로 같은 셀 수·자원 수량을 같은 정밀 시공 면적으로 해석하지 않는다.

### MCLP와 유전 알고리즘

MCLP는 정확해를 보장하는 정수계획 풀이가 아닌 **탐욕적 최대 커버 근사**다. 기본 반경 250 m이며 기준 모델의 고온 영역에서 단위면적당 같은 수요를 가정한다. 수요 가중치는 고온 셀 면적이다. 기존 LST에서 유도된 수요 지수·인구·보행량·취약성 대리변수는 사용하지 않는다. 거점은 변경 셀 수에 따라 최대 8개다. 반경은 계획상 커버 범위이며 실측 냉각 반경이 아니다.

GA는 집단 8개, 6세대의 제한된 탐색이다. MCLP 주변과 고온 위치를 초기 후보에 활용하고 교차·변이 후 표면 종류·중복 제약을 복구한다. **평가되는 고유 후보 배치마다 온도 모델을 평가 시각까지 다시 계산**한다. 최종 선택 배치도 하루 전체 모델로 계산한다.

작게 만들려는 목적함수는 다음과 같다.

```text
면적 가중 평균 LST
+ 0.5 × max(0, LST − 공통 고온 임계값)의 면적 가중 평균
+ 0.05 × 최고 LST
```

모델상 목적함수 개선은 실제 도시 냉각 효과나 전역 최적해의 증거가 아니다. 비교 결과에는 사용 자원, 상대비용, 난수 시드, 평가한 배치 수, 목적함수와 고온 기준을 남긴다.

## 관측과의 비교 및 자료 누출 방지

새 연구 모델은 Landsat 온도를 초기화·물성 적합·잔차 보정에 사용하지 않는다. 각 날짜의 00시 기온으로 시작해 **실제 위성 촬영 시각**까지 적분하며 11:10을 11:00으로 반올림해 비교하지 않는다.

| Landsat 날짜 | 촬영 시각 UTC | 기상 확보 | 비교 상태 |
| --- | --- | --- | --- |
| 2024-08-29 | 02:10:47.890525 | ERA5 당일 자료 | 기준 사례의 보정 없는 비교 가능 |
| 2025-06-05 | 02:10:27.913458 | ERA5 당일 자료 | 다른 날짜에 대한 비교 가능 |
| 2024-06-02 | 02:10:25.461445 | 현재 없음 | 모델 검증 수치 표시하지 않음 |

Asia/Seoul 촬영 시각은 UTC+9다. 둘 다 유효한 경계 내부 셀만 짝지어 MAE, RMSE, 평균편향(모델−관측), R², 개수를 계산한다. R²는 음수일 수 있으며 숨기거나 0으로 자르지 않는다. 같은 원격탐사 자료의 공간 상관성과 모델의 공통 가정 때문에 246셀이 독립된 현장 실험 246개라는 뜻은 아니다.

`validationPolicy`는 2024-08-29를 기준 사례, 2025-06-05를 다른 날짜의 평가 사례로 기록한다. 도시의 재료·공간 입력은 고정돼 있으므로 토지 이용 변화와 계절 차이도 오차에 섞인다. 향후 2025-06-05 관측을 보며 계수를 조정했다면 그 날짜는 더 이상 미사용 검증 자료가 아니므로 새 평가 날짜를 확보해야 한다.

**`guwol-history.sceneMaps`의 결측 대입·평균 채움 결과와 기존 `guwol-data.remoteSensing.lstC`는 새 독립 평가의 정답으로 사용하지 않는다.** 연구실의 LST는 `observations.json`에서 품질 마스크·`null`을 보존해 별도로 집계한 `research-inputs.json`만 사용한다.

## 자유 이동 관측 지도 파이프라인

`index.html`과 `src/observed-app.js`는 연구실 고정 격자와 별개로 현재 화면의 원격 자료를 요청한다. 초기 위치는 구월동 경도 126.7065·위도 37.4479, 줌 15.35이며 URL 해시로 카메라 상태를 보존한다. 지도를 자유롭게 이동할 수 있다.

### 검색, 수신, 장면 보존

- 검색 기준일 기본값은 오늘이며 관측일과 다르다. Microsoft Planetary Computer의 Landsat 8/9 `L2SP`, 열 밴드·QA가 있는 후보를 기준일 ±32일·장면 구름 80% 미만에서 검색한다.
- STAC는 최대 3페이지, 페이지당 100개 후보를 조회한다. 동일 서비스의 다음 페이지 링크만 허용하고 검색 제한 여부를 표시한다.
- 순위 점수는 `기준일과의 거리(일) + 구름 비율(%) × 0.1`이다. 상위 최대 **12개**를 **4개씩 병렬 수신**하고 순위대로 합성한다. 첫 4개가 실패·결측이어도 다음 후보를 시도한다. 화면 99.5%가 채워지면 불필요한 나머지 요청을 취소한다.
- 성공한 각 장면의 **전체 래스터를 별도로 보존**한다. 합성 지도에서 화소 소유 장면만 필터링해 단일 장면이라고 부르지 않는다. 기본 화면은 첫 유효 단일 장면이며 사용자가 다른 장면 또는 ‘여러 장면 합성·탐색용’을 선택할 수 있다.
- 장면별 촬영일·출처, 실패한 장면 수·후보 제한·자료 범위를 표시한다. 합성에서 고온 군집 계산은 비활성화한다.

### 격자와 품질

화면 범위를 EPSG:3857로 투영하고 지상 약 30 m 제공 격자를 목표로 긴 변 48–256픽셀의 요청을 만든다. 큰 화면에서는 256픽셀 상한 때문에 더 거칠어진다. 30 m는 Landsat 열적외선의 독립 원 해상도가 아니다.

수신은 열 DN, QA_PIXEL, 유효 마스크의 uint16 NPY다. `DN >= 293`, 마스크 유효, QA 비트 0–5 없음, 구름 신뢰도 비트 8–9가 중간 미만, 권운 신뢰도 비트 14–15가 높음 미만일 때만 온도로 변환한다. 결측은 `null`이다. 모든 구름 잔여물과 온도 오차를 없앴다고 주장하지 않는다.

### 재사용, 오류와 상태

화면을 사방 20% 넓혀 요청한다. 동일 기준일에 현재 화면을 모두 덮고 해상도가 충분한 성공 자료는 최대 6개 캐시에서 재사용한다. 이동이 끝난 뒤 약 450 ms에 조회하고 이전 요청은 AbortController와 요청 번호로 무효화한다.

이동 중 기존 영상은 좌표에 고정한 채 흐리게 남기되 **이전 조회 영상**으로 표시하고 평균·히스토그램·고온 분석을 비운다. 새 장면 선택과 A/B 채집도 현재 자료가 올 때까지 잠근다. 새 지역 조회 실패 또는 줌 8 미만에서는 이전 온도 레이어·통계를 제거한다. 날짜 변경 때도 이전 자료를 지운다.

### 지도 해석과 A/B 비교

통계는 기울어진 지도에서 실제 화면 사다리꼴 안에 화소 중심이 있는 값이다. 기본 색 범위는 화면의 2–98백분위이며, 장소 비교에는 고정 24–50°C를 쓴다. 범위 밖 값은 끝 색으로 합쳐 범례에 ≤/≥로 표시한다. 열 색은 순차 주황 램프, 상대적 고온 윤곽은 보라색이다.

A/B 선택은 위치·관측값·정확한 장면 ID·촬영 시각을 함께 저장한다. **같은 날짜여도 장면 ID가 다르면 온도 차이를 계산하지 않는다.** 결측·다른 장면이면 이유를 표시한다. 저장한 A/B의 날짜는 지도 날짜를 바꿔도 남으므로 이를 새 화면 평균처럼 읽지 않는다. 위치 차이로 재질의 원인 효과를 단정하지 않는다.

### 3D 건물

OpenFreeMap 밝은 배경 지도와 Overpass OSM 형상을 사용한다. 자유 지도에서는 실제 `height` 태그가 있는 건물·건물 부분만 3D로 표시하며 층수·임의 높이를 대입하지 않는다. 전체 건물 수와 높이 등록 비율을 함께 보여 준다. 줌 13 이상·조회 영역 160 km² 이하에서만 요청한다.

서버는 `overpass-api.de` → `overpass.private.coffee` → `overpass.kumi.systems` 순서, 각 22초 제한이다. 429 응답은 다른 서버로 우회하지 않는다. 요청 간격과 캐시를 유지하며 이동·조회 중·실패 때 이전 지역 건물은 숨긴다. 건물 클릭 온도는 그 위치의 위성 셀 값이지 건물 자체를 따로 측정한 온도가 아니다.

## 한 지점 재료 실험

기존 지도 내 재료 실험은 연구실의 24시간 도시 모델과 구별되는 **정상상태 표면 에너지수지**다. 지면 원 또는 등록 건물 지붕을 선택하고 가정한 기존 재료와 변경 재료를 비교한다. 원 반경은 시각화 범위이고 단위면적 결과를 바꾸지 않는다.

```text
에너지 유입 = (1 − 반사율) × 일사 − 증발계수 × 수분계수  [W/m²]

흡수 일사 + 대기 장파
= 방출 장파 + 대류 + 기층 전도 + 증발
```

선택한 위성 화소의 실제 촬영 시각에 맞춘 Open-Meteo 기상을 사용하며 조회 실패·관측 부재 시 일사 800 W/m², 기온 30°C, 습도 60%, 풍속 2 m/s 등 가정값임을 표시한다. 촬영 시각 기상으로 계산한 경우만 한 화소의 모델−관측 차이를 보여 준다. 이 한 지점 차이는 독립 검증 통계가 아니다.

모델 °C와 W/m²는 서로 다른 변수다. 재료 물성·수분·기층 조건은 가정값이며, 결과는 실제 측정된 냉각이나 검증된 미래 예측, 실내 온도, 보행자 기온·체감온도가 아니다.

## 데이터 재생성

```bash
# numpy, Pillow 설치 환경에서 실행. 공공 원자료 네트워크 접근 필요.
python scripts/build_research_data.py

# 기존 Sentinel·기상을 보존하며 Landsat/null/마스크를 다시 생성
python scripts/build_research_data.py --offline

# 공식 세분류 토지피복만 다시 조회
python scripts/build_research_data.py --offline --refresh-landcover

# 별도로 확보·정합한 공식 토지피복을 가져올 때
python scripts/build_research_data.py --landcover /path/to/aligned-landcover.json
```

원격 응답 캐시는 기본 `/tmp/xy5-research-cache`이며 `--cache`로 바꿀 수 있다. URL과 내용 SHA-256을 기록하지만 캐시는 원자료 영구 보존소가 아니다. Landsat 집계 원본 `data/observations.json`은 저장소에 포함되어 있다. 필요하면 `scripts/build_observations.py`에서 원자료 생성 경로를 확인한다.

토지피복 사용자 자료 형식은 `data/landcover-import.schema.json`이다. `source`, `edition`, `sourceCRS`, `method`, 정확히 일치하는 격자·경계·행 순서, 432개 `classes`, 범례를 요구하며 경계 밖은 `null`이어야 한다. 범주 코드를 쌍선형 보간하지 않는다. 원자료가 없거나 검증에 실패하면 가짜 수치로 채우지 않고 자료 부재를 남긴다. 현재 포함된 공식 WFS 자료는 이 수동 가져오기와 별개로 출처가 기록돼 있다.

### 기존 시뮬레이터와의 관계

`simulator.html`, `src/app.js`, `src/engine.js`, `src/atlas*`는 이전 교육용 구현이며 새 연구실의 계산 엔진이 아니다. 이전 엔진의 **같은 LST 잔차 보정은 기본값에서 껐다**(`calibrateLST: false`). 코드를 통해 명시적으로 켜는 경우에도 같은 장면에 맞추는 기능이지 독립 검증이 아니다. 이전 흐름 애니메이션·모의 지수·보정 수치로 새 모델의 정확도를 뒷받침하지 않는다.

`urban-heat-potential-lab/`은 더 이전 사본이며 배포하지 않는다. `guwol-data.json`의 공간 자료를 새 모델에 사용하더라도 그 안의 과거 LST·지수·높이 사전값이 새로운 실제 측정값으로 바뀌는 것은 아니다.

## 후속 연구

1. 현장 재질·반사율·불투수율·건물 형상 및 기상 측정으로 입력 가정을 검증한다.
2. 다른 계절과 더 많은 촬영일, 사용하지 않은 공간 구역을 확보해 시간·공간 검증을 확대한다. 보정용 자료와 평가 자료를 분리한다.
3. ST_QA와 원자료 품질·정합·재표본 불확실도를 포함한다.
4. 초기 열 저장을 위한 충분한 예열 기간, 상세 그늘·복사·바람장과 민감도·에너지 보존 검사를 확장한다.
5. 실제 비용·시설 크기·설치 가능 구역·인구 수요를 반영하고 탐색 횟수·난수 시드·목적함수에 따른 배치 안정성을 확인한다.
6. 원격탐사 공간 관계를 설명할 때 자료 시차와 공간 자기상관을 통제하고 상관관계를 인과관계로 표현하지 않는다.
